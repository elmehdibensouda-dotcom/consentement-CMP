A ALAMANE inventaire local
OUTIL DE REPÉRAGE · WEB

Inventorier une page autorisée

Ce prototype relève les scripts, iframes, requêtes réseau de type script/fetch/XHR visibles au chargement de la page et les noms de cookies accessibles. Il ne classe pas automatiquement les finalités et n’envoie rien à ALAMANE.

Utilisation

  1. Ouvre dans le navigateur une page que ton organisation est autorisée à examiner.
  2. Ouvre les outils de développement du navigateur, puis l’onglet Console.
  3. Copie le code ci-dessous, colle-le dans la console de cette page et exécute-le.
  4. Classe manuellement les ressources dans le panneau ALAMANE, regarde le signal de marqueur direct, puis copie ou télécharge le rapport JSON.
  5. Pour une démonstration avec des données synthétiques, configure d’abord sur la propriété Web l’origine exacte du site (scheme, hôte et port, sans chemin), puis importe le fichier depuis la console. Le rapport doit correspondre à cette origine ; l’association ne prouve pas le contrôle du domaine.
  6. Relance l’inventaire sur les parcours et états qui t’intéressent. Un scan ne couvre que le chargement de la page où il s’exécute.
Limites : le marqueur ALAMANE est un signal observé dans le DOM, pas une preuve que tous les déclenchements sont bloqués ; un gestionnaire comme GTM peut appliquer un contrôle distinct. Les valeurs de cookies ne sont jamais lues, les cookies HttpOnly ne sont pas visibles, et les résultats restent dans le navigateur jusqu’à une copie ou un téléchargement explicite. Une importation ultérieure conserve le rapport dans la base SQLite locale. Le rapport nécessite une revue humaine ; il ne prouve pas la conformité et ne modifie ni les traceurs ni la configuration du site. N’importe pas d’inventaire réel de banque dans ce prototype.

Ce code est servi depuis le projet local. Vérifie-le avec l’équipe sécurité avant de l’utiliser sur un domaine d’entreprise. Retour à la console entreprise
